**ADR: 2026-11.5 - Выбор асинхронной обработки фоновых задач**

**Дата:** 16 ноября 2026 г.

**Статус:** Принято

**Контекст:**

Уведомления о бронировании, переводы владельцам после завершения аренды, расчет рейтингов и очистка просроченных холдов не должны блокировать HTTP-запросы поиска и бронирования.

**Рассмотренные варианты:**

1. **Redis + Celery:** Стандарт для Django, простота, мониторинг Flower.
2. **RabbitMQ + Dramatiq:** Надежнее доставка, но сложнее инфраструктура.
3. **Kafka:** Избыточно для модульного монолита.

**Решение:**

Выбран Redis + Celery.

**Обоснование:**

- **Нативная интеграция с Django:** Celery — де-факто стандарт для Django. Готовые биндинги, поддержка периодических задач (beat) для напоминаний и автоматических выплат, мониторинг через Flower. Минимум boilerplate-кода.
- **Достаточность для монолита:** Kafka/RabbitMQ нужны для high-throughput streaming или сложной маршрутизации между микросервисами. В модульном монолите объем фоновых задач умеренный; Redis справляется с ними без избыточной сложности.

**Последствия:**

- Необходимо настроить мониторинг очередей и обработку dead-letter задач. Redis должен быть настроен на persistence для критичных задач.
