**ADR: 2026-11.4 - Выбор механизма предотвращения двойного бронирования**

**Дата:** 16 ноября 2026 г.

**Статус:** Принято

**Контекст:**

Критически важно, чтобы два водителя не забронировали одно и то же место на одно и то же время. Конкуренция возникает при одновременных запросах на бронирование.

**Рассмотренные варианты:**

1. **Оптимистическая блокировка:** Проверка версии записи при обновлении. Если версия изменилась, транзакция откатывается. Требует повторной попытки пользователем.
2. **Пессимистическая блокировка:** Блокировка строки в БД на время транзакции. Гарантирует эксклюзивный доступ, но снижает производительность при высокой конкуренции.
3. **Exclusion Constraints:** Это механизм PostgreSQL, который работает ниже уровня приложения. Даже если код Django пропустит конфликт, БД физически не даст вставить пересекающуюся запись.

**Решение:**

Выбрана Exclusion Constraints (как основная гарантия) + Оптимистические блокировки (для UX).

**Обоснование:**

- **Безопасность:** Constraint не даст создать пересекающуюся запись ни при каких обстоятельствах. При каждой записи PostgreSQL проверяет новый диапазон времени против всех существующих диапазонов для парковочного места. Если есть пересечение (&&), транзакция откатывается с ошибкой IntegrityError.
- **Производительность:** Избегаем тяжелых пессимистических блокировок на этапе проверки.
- **UX:** Для пользователя используем версии (оптимистеческая блокировка), чтобы при конфликте версий возвращалась понятная ошибка «Место только что занято», предлагая обновить список.

**Недостатки решения:**

- **Риск очередей:** При высокой конкуренции за популярное место запросы могут выстраиваться в очередь, увеличивая время отклика интерфейса для пользователей.
- **Сложность обработки ошибок:** Приложение должно корректно обрабатывать таймауты блокировок и взаимоблокировки (deadlocks), чтобы не «ронять» сервис.

**Последствия:**

- Код создания бронирования должен обрабатывать IntegrityError и преобразовывать его в пользовательскую ошибку «К сожалению, это место только что забронировали. Пожалуйста, выберите другое».
